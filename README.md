<summary><b>🏆 Deema ATS — Application Intake & Hiring Pipeline (QSTP Hackathon)</b></summary>

<br/>

Led engineering on a 4-day hackathon team project (Qatar Science & Technology Park "Build for QSTP" challenge) building the application-intake and hiring-pipeline layer for **Deema**, a third-party AI resume-ranking product — under a strict "no ranking" scope boundary set by the integration partner.

| Category | Detail |
|:--|:--|
| **Stack** | Next.js 16, React 19, TypeScript, Drizzle ORM, PostgreSQL, OpenRouter, `dnd-kit`, `archiver`, `pdf-lib`, `unpdf` |
| **Scale** | Streamed exports of 2,000 Applications (4,000 files, 6.7MB total) with flat memory |
| **Performance** | 2,000-Application ZIP export streamed in **42.4 seconds** (measured, verified via unzip integrity check) |
| **Security** | Tool-calling agent architected so tool signatures structurally cannot return re-ranking data — scope enforced at the code level, not via prompting |
| **Impact** | Closed the "Deema can't receive applications" gap for a production AI ranking product already used by QSTP |
| **Repository** | [`yousefhakem/QSTP-challenge-2`](https://github.com/yousefhakem/QSTP-challenge-2) |

Built a streaming ZIP export pipeline and a drag-and-drop 5-stage hiring pipeline. Designed an authenticity score from observed authorship signals (paste ratio, composition time) instead of naive AI-detection, avoiding the documented bias of stylistic detectors against non-native English writers.

</details>

|:--|:--|

| **Impact** | Auditable order lifecycle from admission → matching → CDC-driven settlement across wallets, orders, and trade records |

Engineered CDC-driven handoff through Debezium and Kafka, applying settlement in PostgreSQL transactions that update wallets, orders, market prices, and immutable trade records. Containerized the full stack (PostgreSQL 16, Kafka KRaft, Debezium Connect) with Docker Compose.

</details>
